# g2b-daily

나라장터의 **용역 입찰공고 메타데이터**를 매일 한 번 저장하는 작은 공개 데이터 프로젝트입니다. 사람이 손대지 않은 날에도 기록이 쌓이고, 수집이 불완전하면 파일을 만들지 않고 GitHub Actions를 실패시킵니다.

## 공개 경계

이 저장소는 아래 세 가지를 의도적으로 하지 않습니다.

- 특정 품명·예산·기관으로 공고를 거르지 않습니다.
- 추천, 적합도, Go/No-Go 같은 판정을 만들지 않습니다.
- 첨부 파일을 내려받거나 읽지 않습니다. 첨부 URL도 저장하지 않고 개수만 기록합니다.

대상은 조달청 [나라장터 입찰공고정보서비스](https://www.data.go.kr/data/15129394/openapi.do)의 `getBidPblancListInfoServc` 오퍼레이션입니다. 공식 명세에 따라 등록일시(`inqryDiv=1`)와 변경일시(`inqryDiv=3`) 두 수로를 모두 조회합니다. 공고 상태는 API가 제공하는 `등록공고`, `변경공고`, `취소공고`, `재공고` 값을 사실 그대로 보존합니다.

## 매일 저장되는 것

`snapshots/YYYY-MM-DD.jsonl`에 다음 값만 저장합니다.

- 공고번호·차수·공고명과 공고 상태
- 공고·등록·변경·입찰 시작·마감·개찰 시각
- 공고기관·수요기관 코드와 이름
- 추정가격·배정예산 필드 값
- 사전규격등록번호
- 첨부 필드가 채워진 개수
- 수집일시, 스키마 버전, 등록/변경 중 어느 조회에서 관찰됐는지

빈 필드는 `null`입니다. 이는 “원문에 정보가 없다”가 아니라 **API 응답 필드가 비어 있었다**는 뜻입니다.

## 안전장치

- API 오류나 예상하지 못한 응답 구조면 실패합니다.
- 각 페이지의 `totalCount`가 수집 중 바뀌면 실패합니다.
- 받은 행 수와 `totalCount`가 다르면 실패합니다.
- 페이지 사이에 공고번호·차수 중복이 생기면 실패합니다.
- 정상 응답의 `totalCount`가 등록·변경 모두 0이면 날짜가 붙은 빈 jsonl을 커밋합니다. 실패한 날은 파일 자체가 생기지 않습니다.
- 같은 날짜의 스냅샷은 덮어쓰지 않습니다.
- 두 조회가 모두 끝난 뒤에만 임시 파일을 원자적으로 최종 파일로 바꿉니다.

## 실행

Python 3.11 이상만 필요하며 런타임 의존성은 없습니다.

```bash
python -m pip install -e .
export DATA_GO_KR_SERVICE_KEY="공공데이터포털에서 발급받은 키"
python -m g2b_daily
```

기본값은 한국시간 기준 어제 하루(`00:00`~`23:59`)입니다. 특정 날짜를 수집하려면 다음처럼 실행합니다.

```bash
python -m g2b_daily --date 2026-09-01
```

테스트:

```bash
python -m unittest discover -s tests -v
```

## GitHub Actions 설정

1. 공공데이터포털에서 `조달청_나라장터 입찰공고정보서비스` 활용신청을 합니다.
2. 저장소의 **Settings → Secrets and variables → Actions**에서 `DATA_GO_KR_SERVICE_KEY`라는 Repository secret을 만듭니다.
3. **Actions → Daily G2B snapshot → Run workflow**로 첫 실행을 확인합니다.

워크플로는 매일 한국시간 09:30에 전날 기록을 수집합니다. 키는 요청에만 사용되고 로그나 스냅샷에 기록되지 않습니다.

## 현재 범위

현재 버전은 수집과 자동 커밋까지인 v0-a입니다. 장기 지표나 화면은 데이터가 충분히 쌓인 뒤 추가합니다. 특히 공고 상태가 API 응답에 남기 때문에, 단순한 날짜 간 차집합을 곧바로 “삭제”나 “소멸”로 해석하지 않습니다.
